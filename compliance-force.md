Implementation Map

Blindagem contra vínculo trabalhista: Models/DB = Booking com scheduledStart, status e índices (schema.prisma (lines 523-620)); Endpoints = POST /bookings + status updates via BookingsController/BookingsService; Rules = ensureWeeklyLimit + runWithWeeklyLock invoked before persistence/confirmation; Logs/Auditoria = [BookingsService] weekly limit violation warnings and telemetry booking_status_updated.
KYC / identidade: Models/DB = Provider carries document/selfie URLs + verificationStatus + enums (verification-status.enum.ts); Endpoints = registerProvider + VerificationController actions; Rules = registerProvider seeds PENDING_INITIAL_REVIEW, VerificationService updates statuses after uploads, manual approvals add rejection reasons, BookingsService refuses non-APPROVED providers; Logs/Auditoria = log keys in VerificationService/BookingsService and ProvidersService.getPendingProviders.
Evidências operacionais: Models/DB = Booking timestamps, BookingProof (photos/timestamps/hashes), Address lat/lng; Endpoints = /bookings/:id/proof/{checkin,checkout}, arrive/start/complete flows; Rules = arriveAtLocation, startService (proof/payment window), completeService (checkout proof video, payment, expected end), BookingProof creation with hash/timestamp storage; Logs/Auditoria = logs on proof creation and scheduler notifications for start/end.
Seguro / claims: Models/DB = BookingInsurance, InsuranceClaim, InsurancePlanId enum; Endpoints = insurance plans controller + /incidents (create/get); Rules = InsuranceService evaluates plan eligibility, booking creation attaches insurance, IncidentsService.createClaim enforces 24h window, proof requirements, deductible logic; Logs/Auditoria = log statements describing claim status and automatic UserRole checks.
Rastro financeiro / antifraude: Models/DB = PaymentIntent, LedgerEntry, Payout references; Endpoints = payments routes + disputes endpoints; Rules = PaymentIntentLocker + createPixCharge idempotency, handlePaymentWebhook HMAC/ledger, updateStatus ledger EARNING/HOLD/RELEASE/REFUND, DisputeService holds/releases, DisputeController accepts Idempotency-Key; Logs/Auditoria = Payments webhook logs warning on duplicate intent, ledger warnings in disputes, notifications enqueued with idempotency keys.
Desintermediação: Models/DB = Chat + Booking statuses; Endpoints = ChatService use in /chat controller + /disputes; Rules = chat gating to confirmed bookings, DisputeService auto-creates tickets/messages and notifies admins, IncidentsService forces claims to go through platform; Logs/Auditoria = chat logs referencing blocked access, dispute logs referencing notifications.
Contratos/políticas: Models/DB = UserConsent; Endpoints = TBD (service not yet exposed); Rules = ComplianceService.recordConsent/checkConsent, DSAR, erasure flows; Logs/Auditoria = service logs consent/DSAR/erasure actions.
